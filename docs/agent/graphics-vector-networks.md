# Vector networks

`/graphics/network` provides an editable undirected multigraph above `Path`. Vertices have stable positive IDs and positions. Segments have stable IDs, two vertex references, and endpoint-relative cubic tangents. IDs are local to a network and are never recycled; a copy preserves IDs and owns independent storage. Self-loops, parallel edges, isolated vertices, and disconnected components are supported.

Use `vertices` and `segments` to enumerate value snapshots, and `vertex(id)` or `segment(id)` to retrieve one. Mutation goes through the network methods and increments `revision`. Missing IDs, nonfinite coordinates, invalid split/bend parameters, and invalid handle pairs panic before changing geometry. Numerical coordinates and tangents must remain finite.

`connect` never welds geometry by position. `merge-vertices` explicitly rewires a source into a destination at the supplied position, preserving endpoint-relative tangents. `disconnect` detaches one segment end into a new coincident vertex. `remove-vertex` removes incident segments; it does not heal a curve. `split` preserves cubic geometry, keeps the first segment's identity, creates the second segment, and carries source interval provenance. Self-loop ends are distinguished by `NetworkEnd.at-end`.

A `NetworkPair` relates two specific handles at one vertex. Angle-only pairing preserves the other handle's length; length mirroring makes the lengths equal. `set-handle` applies the pair unless independent editing is requested. No pair is inferred between unrelated branches. `bend` changes control handles to move the point at the supplied curve parameter by the requested displacement, minimizing squared handle movement among unlocked handles. Anchors stay fixed. Handle pairs are preserved by default and can be explicitly ignored. Bending a self-loop whose two ends are paired requires independent-handle mode; the constrained request otherwise fails atomically.

`pick` returns a segment ID, cubic parameter, position, and distance, with a geometric search resolution of approximately 0.00001 document units and a bounded subdivision depth. Picking includes endpoints. `network-from-path` preserves subpath boundaries and closure without welding coincident vertices. `traces` decomposes each edge once into maximal degree-two chains, with a source ID and reversal flag for each emitted curve. `geometry` combines those traces. Paths preserve appearance, not editable graph identity.

# Regions

`/graphics/network-regions` exposes `NetworkRegionWorkspace.resolve(network)`. It derives a planar arrangement from segment intersections while leaving the editable graph unchanged. Region boundaries retain source segment intervals and direction. Cubic ranges remain cubic in output. Geometric intersections within the workspace's positive tolerance (default 0.00001 document units) share derived arrangement nodes; this never welds editable vertices. Features below that tolerance may collapse. Zero-size edges are ignored for face construction, coincident fragments contribute one geometric boundary, and dangling branches do not create regions.

Each bounded face has a closed `Path`, including negatively oriented hole boundaries. `pick` identifies a face independently of whether it is painted. Treat resolved snapshots and their paths as read-only. A workspace owns one network's region history; using it for another network starts a new correspondence history. `copy-for` carries that history to an exact copied network for undo snapshots. Clear the workspace to release retained network and result references.

Correspondence uses overlapping source boundary intervals and direction, with spatial containment for newly introduced boundaries. One-to-one correspondence retains the region ID. Splits and merges produce fresh IDs and explicit predecessor lists. `retired` identifies IDs no longer used. Correspondence describes geometry ancestry, not paint policy. Consumers propagate matching assignments, inherit a split parent's assignment, and resolve differing merge assignments. Arbitrary geometric edits can be ambiguous; predecessor lists expose that ambiguity rather than selecting a paint silently.

# Combining

`add-network` copies another network in with fresh vertex and segment ids, remapping sources and pairs. `cut` splits one segment at increasing interior parameters and disconnects the pieces, returning their segment ids in order. `extract` copies one trace into its own network with its ids, pairs, and direction. `NetworkRegionWorkspace.crossings` reports each interior point where segments meet, one entry per segment, with a shared `crossing` id for entries at the same place; endpoints on another segment count for that segment only.

`/graphics/network-combine` builds on these. `network-join` grows the open run holding a given end at both of its ends, each time taking the closest pair of a run end and another open run's free end, merging ends within a tolerance and bridging the rest with straight segments; it never connects the run's own ends, and then reorders the run's vertices along it with `order-vertices` so the run keeps its direction. `network-split` cuts a network at its crossings and returns one network per trace. `network-weave` merges several networks, cuts each strand halfway between its crossings by arc length, and returns pieces marked over or under so that over and under alternate along each strand and differ at each two-visit crossing, under pieces first.

# Strokes

`/graphics/network-stroke` constructs a closed uniform centered stroke outline suitable for filling through existing Canvas backends. Degree-two chains use the path stroker. At branching vertices, incident curves are angularly ordered, adjacent pairs contribute joins, and consistently oriented pieces combine coverage under the nonzero fill rule. Caps apply only at degree-one endpoints. Round, bevel, and bounded-miter joins and butt, round, and square caps are supported. Render the resulting compound outline once with the nonzero fill rule, without an additional stroke, to avoid compositing overlap multiple times. Use `path.contains(point, FillRule.nonzero)` for matching hit testing. The contours may overlap; this is filled coverage, not a canonical Boolean boundary.

`NetworkStrokeWorkspace` caches outlines by network identity, revision, width, cap, join, and miter limit. Returned paths are read-only snapshots. Region workspaces reuse intersection scratch; changed geometry currently triggers full arrangement/stroke reconstruction. Vertex and edge lookup are linear, region intersection discovery is pairwise, and stroke assembly grows with the number of chains and junctions. This initial implementation targets small drawing networks; it is not an incremental large-document engine. The `graphics/network-editing` benchmark measures the cost of a fixed 24-edit, eight-segment scene.

Variable-width junctions, dashed network traversal, automatic curve healing, and Boolean editing of the network itself are outside this version.
